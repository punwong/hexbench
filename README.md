## 一句话介绍

一个常驻托盘的 Windows 效率工具箱。**第一个工具**：鼠标推到屏幕最外侧边缘的角落区，就切换虚拟桌面。多显示器横竖混排、任意摆放都零配置，插拔副屏自动适应；配一套刻意设计过的图形界面，配置可经 WebDAV 跨设备同步。

---

## 一、为什么做这个

### 起点：我用 Quicker 做了一个，它能用

那个动作靠**手工录入四个外角点**工作：竖屏的左上、左下 + 横屏的右上、右下。配合「边缘上限 90% / 下限 100%」，把触发区限制在各屏最底部的 10%。

这个做法在数学上是正确的，而且挺巧——左边缘的垂直限位用竖屏自己的上下边界，右边缘用横屏自己的上下边界，两块屏各算各的，互不干扰。**实测零误触发。**

### 但它有绕不过去的成本

| 问题 | 代价 |
| --- | --- |
| 必须装 Quicker 并保持常驻 | 本机实测 **210 MB** 工作集（可用内存只剩 3.4 GB / 31.8 GB） |
| 首次使用要手工录 4 个角点 | 插拔副屏、改分辨率、转屏、换电脑，**全部要重录** |
| 按主机名分别保存方案 | 换台机器等于从零开始 |
| 界面是通用表单 | 没有针对这个功能的界面设计 |

### 现成的开源项目，没有一个正好落在需求上

| 项目 | 做法 | 差距（读源码确认） |
| --- | --- | --- |
| **winxcorners**（951★）<br>**Convenient Window**（192★） | 按每块屏的矩形直接算四角 / 四边热区 | **从不判断"这条边外面还有没有另一块屏"** → 内部接缝被当成边缘，误触发 |
| **DeskBorder**（7★） | 只取全局最外侧的边（左右边逻辑正确） | 上下边没做同样判断；C# WPF，常驻 30–60 MB；**没有现成安装包** |
| **Quicker 动作** | 手工标定四个外角点 | 正确，但要宿主 210 MB + 手工录点 |

> 星数、内存等数据截至 2026-10，仅作横向参考。

缺口很明确：**没有一个独立、零配置、能正确处理非矩形布局、并且界面做得像样的工具。**

## 二、核心思路

### 2.1 把你手工录的那 4 个值，自动算出来

这是整个项目唯一的技术主张。手录四个角点本质提供四类信息，而这四类信息系统 API 全都知道：

| 你手工录的 | 程序自动算 |
| --- | --- |
| 「最左边缘」的 X | 该屏左边仍在虚拟桌面范围内的部分（见 2.2） |
| 「最右边缘」的 X | 该屏右边仍在虚拟桌面范围内的部分（见 2.2） |
| 左边缘的垂直范围 | **光标所在屏 `M`** 的触发带（默认底部 10%） |
| 右边缘的垂直范围 | 同上，仍是 `M` 的触发带 |

> **关键在最后两行**：垂直范围不取整块虚拟屏的高度，而取「光标此刻所在那块屏」的高度。这正是「每块屏各录自己的上下角」所做到的等价效果。

### 2.2 边缘判定：探头分段（唯一模型）

不做 `min/max` 的简化版，直接判定「这条边在这一段外面还有没有屏」——探针法既是 `min/max` 的推广，也是布局图绘制触发带的同一份数据。

```c
// 左侧：边外第一列
leftExposed (M, y) = MonitorFromPoint({ M.left - 1, y }, MONITOR_DEFAULTTONULL) == NULL;
// 右侧：边外第一列（注意是 M.right，不是 M.right - 1）
rightExposed(M, y) = MonitorFromPoint({ M.right,    y }, MONITOR_DEFAULTTONULL) == NULL;
```

一条边可能被切成若干段：取所有显示器的 `top` / `bottom` 作为断点并排序，逐段用中点探一次，合并相邻的「暴露段」。显示器数 ≤ 8，O(n²) 可以忽略。

判定逻辑：

```
每 50 ms:
    (x, y) = GetCursorPos
    if 已暂停 / 冷却中 / 鼠标按键按下 / 前台全屏 / 前台进程在黑名单 / 锁屏 → 跳过

    M = 包含 (x, y) 的那块显示器
    if M 不存在 → 跳过

    inBand = (y >= M.bottom - M.height * ratio) and (y < M.bottom)     // 默认底部 10%
    onTaskbar = 光标落点属于任务栏窗口（Shell_TrayWnd / Shell_SecondaryTrayWnd / TrayNotifyWnd ...）

    if inBand and not onTaskbar:
        if x in [M.left, M.left + 1]      and leftExposed(M, y)  → 交给状态机，方向 = 上一个
        if x in [M.right - 2, M.right - 1] and rightExposed(M, y) → 交给状态机，方向 = 下一个
```

三行判断解决三个问题：

- **只有真实外边缘触发**：探头为 `NULL` 才命中，内部接缝永远不命中（不是靠 `min/max` 特判）
- **触发带用 `M` 自己的高度**：每块屏比例一致，横竖混排各算各的
- **`M` 从光标实时查**：布局变了自然正确，不需要任何标定

两处实现细节：

- 边缘判定给 1~2 px 容差（`M.left + 1`、`M.right - 2`），避免高 DPI 下 `GetCursorPos` 与 `GetMonitorInfoW` 的取整差 1 px 导致永远不命中。
- 右侧探针用 `M.right`：那是边外的第一列。用 `M.right - 1` 会永远探到自己。

### 2.3 触发状态机

**只靠「冷却 + 电平」是不够的**：冷却结束后光标还停在触发区，会再切一次——鼠标停在角落不动，桌面就会连续翻滚。所以触发必须是「进入 → 停留 → 触发 → 必须离开才能复位」的状态机。

```
           进入触发区                 停留 ≥ dwell
  Idle ───────────────> Armed ──────────────────> Fire
    ↑                     │                        │
    │     提前离开         │                        │ 一次性提交 4 个按键
    └─────────────────────┘                        ↓
    ↑                                          Disarmed
    │                                             │
    └──────── 光标离开触发区 ≥ 复位距离 ───────────┘
```

| 规则 | 值 / 行为 |
| --- | --- |
| 进入 → 停留阈值 `dwell` | 默认 **120 ms**，可配 0–500 |
| 触发 → `Disarmed` | 一次只发一次，`SendInput` 四个按键**一次提交**，检查返回值 |
| 复位条件 | 光标离开触发区 **≥ 24 px**（或离开该边缘），不是靠时间 |
| 冷却 `cooldown` | 默认 **500 ms**（> 系统切换动画），从 Fire 起算，只防抖不负责复位 |
| 光标回位 | 触发后向内推 **24 px**（可关）——这一步本身就是「离开」，顺带完成复位 |
| 发送失败 | `SendInput` 返回 0 时记日志 + 一次性提示「切换被系统拦截」，不静默 |

> 回位只在**由本程序触发**时执行，且可关；关掉后仍要靠「移动离开」复位。

### 2.4 为什么不需要手工标定

"这条边外面有没有屏"不是主观判断，是系统能客观回答的事实（就是 2.2 那两行）。探头法默认开启，不再作为"增强模式"留到 v0.5——否则核心判定要在发布前重写一遍，布局图组件也得跟着改两次。

## 三、几何验证（开发机布局）

以下数据由 `hexbench --layout --demo` 生成（示例布局），避免文档与实现漂移。

```
屏 0 (横屏, 主屏)   L 0      T 0      R 3440   B 1440    3440 × 1440
屏 1 (竖屏)         L -1080  T -232   R 0      B 1688    1080 × 1920
```

触发带 = 每屏底部 10%，探头分段后的结果：

```
屏 0  左边缘 x=0      ❌ 内部接缝（左边是竖屏）        带内 0 px
屏 0  右边缘 x=3439   ✅ 外露 1440 px                 带内 144 px（10%）
屏 1  左边缘 x=-1080  ✅ 外露 1920 px                 带内 192 px（10%）
屏 1  右边缘 x=-1     ✅ 外露 480 px（232 + 248）      带内 192 px（10%）
```

> **为什么是三条可触发边段，而不是两条**：竖屏右下角（x=-1，y=1496~1688）的右边确实没有屏——屏 0 只到 y=1440。这是真实外边缘，手录四角没覆盖到它而已。探头法把它算进来是正确行为；该段只有光标能到达时才生效（显示器排布的空隙能否进入由系统决定），到不了也永远不误触发。
>
> **内部接缝仍然是 0**：屏 0 的左边缘在 x=0 处外侧是竖屏，屏 1 的右边缘在 y=0~1440 处外侧是屏 0，两处都不会命中。与手录四角的结论一致。

## 四、功能

- **推到最外侧边缘即切** —— 鼠标推到最左 / 最右屏幕边缘的角落区，切换上一个 / 下一个虚拟桌面
- **多显示器零配置** —— 横竖混排、L 形、错位、上下堆叠，都不需要对屏、不需要录点
- **内部接缝永不误触发**
- **触发比例按屏独立** —— 每块屏用自己的高度算触发带，手感一致
- **布局变化自动适应** —— 插拔副屏、改分辨率、转屏、改缩放，监听 `WM_DISPLAYCHANGE` 重算
- **可视化设置界面** —— 真实比例的显示器布局图，实时显示可触发边缘
- **测试模式** —— 只高亮不切换，用来熟悉触发区、排查误触
- **WebDAV 配置同步** —— 多台设备共用一套行为参数
- **全局热键集中管理** —— 所有快捷键在「全局 → 热键」注册，暂停、话术面板各占一个，工具再多也不互相抢组合键
- **一键更新** —— 关于页点「更新到 x.y.z」：下载、静默安装、自动重启，全程不弹安装向导
- **首次使用引导** —— 第一次装完弹一次主界面，讲清楚该往哪推，之后不再打扰

**工具二：快捷语面板**

- **吸附在聊天软件旁边** —— 选一个应用（如千牛），它在前台时面板自动贴到窗口右侧 / 左侧；**外侧**贴在窗口外，**内侧**叠在窗口边缘往里展开
- **选应用很省事** —— 列表支持按进程名 / 窗口标题搜索，也可以点「拾取窗口」后直接点屏幕上的目标窗口；同时记下窗口类名，应用改名也不受影响
- **面板能收起** —— 标题栏左侧的六边形图标点一下就缩成 72×72 的图标（带条数角标），再点图标展开；直接切换、不做动画
- **拖动位置记忆** —— 拖到哪、下次启动就回到哪
- **点话术默认只填入** —— 用 Unicode 输入打进当前输入框，**不经过剪贴板**；面板右上角的 ↵ 开关（或主界面「点击话术」）可切换成「填入并发送」，发送就是再按一次回车
- **不抢焦点** —— 面板是 `WS_EX_NOACTIVATE` 窗口，点击时焦点仍留在聊天输入框
- **话术可编辑** —— 主界面「快捷语」里加 / 改 / 删，面板 1.5 秒内自动同步

体验细节：托盘常驻（左键打开主界面、右键菜单）、开机自启、防误触（拖拽 / 全屏 / 进程黑名单 / 锁屏）、切换后光标回位、暂停热键、切换失败提示、首次使用引导、亮暗主题跟随系统。

## 五、范围：做什么、不做什么、怎样算成功

### 工具集边界

第一版只做「边缘切桌面」一个工具，把托盘壳、配置、布局图这套底座打磨好；后续按需增加同类效率小工具，但**第一版不做插件机制**，也不对外提供第三方接口。

### 非目标（明确不做）

- macOS / Linux
- 「当前是第几个桌面」的 HUD —— 需要未公开 `ImmersiveShell` 接口，每个 Windows 版本都要适配
- 窗口管理 / 平铺 / 布局记忆
- 触控与触控板手势
- 多套配置方案（导航留槽位，第一版不实现）
- 自建云同步（只用用户自己的 WebDAV）

### 成功标准

| 指标 | 目标 | 验证方式 |
| --- | --- | --- |
| 误触发 | ≤ 1 次/天 | 自用 7 天日志 |
| 触发 → 开始切换 | ≤ 150 ms（P95） | 打点日志 |
| 托盘常驻 | 工作集 ≤ 20 MB，私有 ≤ 5 MB | 空闲 5 分钟后读一次 |
| 安装包 | ≤ 15 MB | 构建产物 |
| 首次使用 | 零配置即可触发 | 新机器/新用户实测 |
| 长稳 | 72 h 无句柄、内存增长 | 压测脚本 |

## 六、技术栈

### 选型依据

要做"好看、现代化"，Web 技术栈是唯一顺路的选择，而 Tauri 是 Rust 侧最成熟、热度最高的 WebView 方案：

| 指标 | Tauri 2 |
| --- | --- |
| 版本 / 迭代 | 2.12.5 · 2026-10，高频更新 |
| crates.io 下载量 | **3,808 万**（Rust GUI 框架最高） |
| 渲染 | 系统 WebView2，不打包浏览器内核 |
| 托盘 | 官方 `TrayIconBuilder` |

**参考项目：CC Switch**（`farion1231/cc-switch`，14.7 万星，v4.0.18）采用了完全相同的技术栈，被大规模实际使用验证过**工程品质（稳定、轻量）**。

> 注意：CC Switch 可以作**技术参考**，但**不作视觉参考**——它的界面是工具型后台风格，不是我们要的观感。技术栈提供"能做到"，做不做好看要靠第七节的设计规范。

### 同类项目的实际选择（2026-10 查）

做技术选型前先看真实项目怎么选，避免拍脑袋：

| 项目 | 类型 | Win32 绑定 | 仓库结构 |
| --- | --- | --- | --- |
| **cc-switch**（Tauri 2） | 托盘常驻的 CLI 切换器 | **`windows-sys` 0.61** + `winreg` | 单个 `src-tauri` crate |
| **clash-verge-rev**（Tauri 2） | 大型代理客户端 | **`windows` 0.62 + `windows-sys`** + `windows-service` | workspace，按业务拆多个 crate |
| **EcoPaste**（Tauri 2） | 剪贴板管理器，托盘 + 自动启动 | **`windows` 0.52** + `winapi` 0.3 | 单个 `src-tauri` crate |
| **komorebi**（纯 Rust） | Windows 平铺窗口管理器 | **`windows` 0.62** | workspace，9 个 crate |
| **Spacedrive**（Tauri 2） | 大型文件管理器 | — | 大 workspace（`core` / `apps/tauri/src-tauri` / `crates/*`） |

三条结论：

1. **没有项目手写 FFI**，全部用 `windows` 或 `windows-sys`。自己维护结构体布局和函数签名是没必要的风险。
2. **`windows-sys` 用于"薄绑定"**（只要几个函数、不想付包装层成本），**`windows` 用于"富 API"**（COM、DWM、Direct2D）。两者可以共存。
3. **核心逻辑单独 crate** 是中大型项目的共同做法（clash-verge、komorebi、Spacedrive）；小工具（cc-switch、EcoPaste）则一个 crate 放完。我们拆 `hexbench-core`，是因为它要脱离 UI 做单测、还要给 CLI 用。

### 平台约束（已确认的边界）

| 约束 | 影响 | 处理 |
| --- | --- | --- |
| Mica 仅 Windows 11 22H2+ | Win10 无毛玻璃 | Win10 降级 Acrylic（1809+），再不行纯色 |
| Windows 10 已于 2025-10 结束支持 | 测试成本翻倍 | **主目标 Win11**，Win10 尽力（不承诺像素级一致） |
| `SendInput` 可能被 UIPI 拦截 | 前台是提权窗口 / UAC 时切换无效 | v0.1 实测；失败检测 + 提示；文档写明。**不申请 `uiAccess`**（要装进 Program Files + 签名，与 per-user 免 UAC 冲突） |
| 自绘标题栏会丢 Snap Layouts / Aero Snap / 双击最大化 | 系统手感退化 | 优先用系统标题栏 + Mica；确需自绘则用社区 overlay 方案并补齐行为，先做原型验证 |
| `titleBarStyle: "Overlay"` 在 Windows 上是否生效 | 未知 | 实现前先做最小验证，不写死在方案里 |
| CSS `AccentColor` 系统色在 WebView2 的可用性 | 不可靠 | 改为 Rust 读注册表强调色，注入 CSS 变量 |

### 关键架构：托盘常驻 + 主窗口按需创建

Tauri 2 的窗口列表留空——**启动后只有托盘图标，不创建任何 WebView**。用户点托盘菜单「打开主界面」时才用 `WebviewWindowBuilder` 创建主窗口；关闭时销毁 WebView、回到纯托盘状态。

| 行为 | 状态 | 内存 |
| --- | --- | --- |
| 开机自启 / 启动 | **只有托盘，不弹窗** | 13~16 MB |
| 打开主界面 | 创建 WebView 并显示 | +80~120 MB |
| 关闭主界面 | 销毁 WebView，回托盘 | 回到 13~16 MB |

> **开机自启绝不弹窗**——否则每次开机都被一个窗口挡住。主界面是「打开来看、关掉回收」的形态。首次安装除外：引导只在第一次运行弹一次。

**已实测验证**：`windows: []` 的 Tauri 2 应用运行时，`msedgewebview2` 进程数零新增，常驻内存 **11.3 MB 工作集 / 1.9 MB 私有**。

配套要点：

- 窗口 `visible: false`，前端 ready 后再 `show()` —— 消除启动白屏闪烁
- 关闭主窗口 = 销毁 WebView 而非退出进程；**延迟 3~5 分钟再回收**，二次打开是热的（`visible:false` 只解决闪烁，不解决按需创建的开销）
- 标题栏方案先验证再定（见上表），不自作主张

## 七、主界面与设计规范

### 信息架构

侧边栏分**「工具」和「全局」两层**，第一版只有「边缘切桌面」一个工具，加新工具时只加一组，全局部分不动：

```
┌────────────────┬─────────────────────────┐
│ 边缘切桌面       │                         │
│   概览          │                         │
│   触发          │      当前页面内容        │
│   防误触        │                         │
│ ─────────────  │                         │
│ 全局            │                         │
│   通用          │                         │
│   同步          │                         │
│   关于          │                         │
└────────────────┴─────────────────────────┘
   ↑ 工具是一组，加新工具就往下加一组
```

| 页面 | 内容 |
| --- | --- |
| **概览**（工具内） | 主开关 + 运行状态 + **显示器布局图**（视觉主角）+ 测试模式入口 + 本次运行切换次数 |
| **触发**（工具内） | 触发带比例 / 位置（底部·顶部）、停留阈值、冷却时间、轮询间隔、左右侧开关、单屏开关 |
| **防误触**（工具内） | 拖拽时禁用、全屏时禁用、任务栏排除、进程黑名单、锁屏暂停 |
| **通用**（全局） | 主题、语言、开机自启、暂停热键、日志目录 |
| **同步**（全局） | WebDAV 地址 / 用户名 / 密码、上传、下载（v0.4） |
| **关于**（全局） | 版本、检查更新、自检（发送一次切换并报告结果）、许可证、开源致谢 |

**预留扩展槽位**（不实现，但导航结构留好）：方案（多套配置一键切换）、统计、快捷键编辑、外观主题。

**导航用侧边栏而非顶部标签**——未来工具和页面变多时顶部标签会挤爆，侧边栏只需往下加。

**第一版不引入路由**：页面用 `useState` 切换即可。等工具超过 3 个或需要深链接唤起时再上 `react-router`。

### 视觉

技术栈只提供能力，观感必须单独定。以下为硬约束，编码时不得自行发挥。

| 项 | 规范 |
| --- | --- |
| 窗口材质 | **Mica**（Win11 22H2+）→ **Acrylic**（Win10 1809+）→ 纯色兜底；跟随系统主题 |
| 强调色 | **从注册表读取系统强调色**（`ColorizationColor` / `AccentColorMenu`）注入 CSS 变量，深浅各一套；不依赖 `AccentColor`，不自造品牌色 |
| 中性色阶 | 一套灰阶，浅色 / 深色各一套，跟随系统主题 |
| 语义色 | 成功 / 警告 / 危险各一，仅用于状态，不用于装饰 |
| 字号 | 12 说明 · 13 标签 · 14 正文 · 16 区块标题 · 20 页面标题 |
| 字重 | **只有三档**：400 正文 / 600 强调 / 700 标题（不用 650——Win10 的 Segoe UI 会落到 700，白定） |
| 字体 | `Segoe UI Variable` → `Segoe UI` → 系统无衬线；Win10 不做逐字重补偿 |
| 间距刻度 | **只用** 4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | 卡片 12px · 控件 8px · 徽章 6px · 窗口圆角交给系统 |
| 阴影 | 只有两档：卡片一档、浮层一档 |
| 窗口 | 默认 960 × 640，最小 820 × 560，可缩放 |

### 动效

统一 spring 参数，全项目只有一套：

```js
{ type: "spring", stiffness: 400, damping: 30, mass: 0.8 }   // 约 5~8% 过冲
```

| 规则 | 说明 |
| --- | --- |
| 时长上限 | **300 ms**，超出的必须改短 |
| 允许动的地方 | 窗口进出、面板展开收起、开关切换、滑块数值平滑、布局图变化、触发瞬间闪烁一次 |
| **禁止** | 循环动画、装饰性动画、超过 2 个元素同时大幅位移、入场逐项延迟超过 4 项 |
| 降级 | 系统「动画效果」关闭或 `prefers-reduced-motion` 时，全部退化为瞬时切换，spring 不生效 |
| 原则 | 快而不炫 —— 设置面板"点了立刻有反应"比"表演"重要 |

### 布局图（界面的视觉主角）

主界面的概览页核心不是表单，是这张图：

- 按**真实显示器坐标等比映射**到画布（SVG，不用 Canvas）
- 显示器轮廓：1.5px 描边 + 8px 圆角 + 极淡填充，标注设备名与分辨率
- 触发带：贴着边缘的半透明色块（强调色 20% 填充 + 1px 描边），**按探头分段逐段绘制**——接缝处断开，不做整条边
- **可触发区用强调色、被禁用的屏灰掉、内部接缝不画触发带并标注为"接缝"**
- 光标位置：小圆点 + 十字准线，主程序每 50 ms 通过 Tauri event 推送
- 命中触发区时：对应边高亮闪一次（一次性，不循环）
- 拖动比例滑块：触发带高度带 spring 平滑变化
- **极端比例**：3440 横屏 + 1080 竖屏并排时，竖屏只有横屏的 1/3 宽。画布自动适配 + 每块屏最小可视宽度，hover 放大；不靠等比硬缩
- **测试模式**：布局图进入"只演示"状态，命中触发区只高亮、不切换，并显示"如果现在松手，会切到哪个方向"

### 首次使用

触发区是看不见的，第一次装完必须讲清楚：

1. 首次运行弹一次主界面（仅一次，不影响"自启不弹窗"）
2. 布局图上高亮可触发区 + 一句"把鼠标推到高亮区，停 0.1 秒"
3. 提供 30 秒的"试一试"流程：推过去 → 高亮 → 告诉用户成功了
4. 之后不再打扰

### 不做的事

- 不做屏幕覆盖层（会为每块屏拉起一套 WebView2 进程，内存涨一个数量级）——可视化全部在主界面内完成
- 不做"当前是第几个桌面"的 HUD（见第五节非目标）
- 不替用户改系统的动画设置；切换动画由 DWM 控制，只能给出手动关闭的说明

## 八、配置、同步与安全

### 单一事实源

**只保留一份配置**：`%APPDATA%\io.github.<user>.hexbench\config.json`。不用 `tauri-plugin-store` 再存一份——两份事实源是 bug 温床。

- 写入：`config.json.tmp` → flush → rename 覆盖，保留 `config.json.bak`
- 读取：失败或校验不过时回退 `.bak`，再不行用默认值并提示
- 兼容：`serde(default)` + 未知字段透传，旧版本读到新配置不会清空
- 密码：单独文件 `credentials.bin`，DPAPI（`CryptProtectData`，`CRYPTPROTECT_UI_FORBIDDEN`），**永不出现在 config.json**

### 同步

**显示器坐标绝不进配置文件**——运行时自动计算。所以配置天然设备无关：

| ✅ 同步 | ❌ 不同步 |
| --- | --- |
| 触发带比例 / 位置、停留与冷却、轮询间隔 | 显示器坐标（运行时算） |
| 防误触开关、暂停热键、进程黑名单 | **WebDAV 密码**（DPAPI 本地加密） |
| 界面语言、主题、开机自启 | **每屏开关**（另一台机器的 `DISPLAY1` 不是同一块屏） |

> **每屏开关只存本地**，键用 EDID（厂商 + 型号 + 序列号）而不是 `\\.\DISPLAY1`——线序、显卡口一变名字就换，同型号双屏还会重名。跨设备同步一个按名字匹配的开关没有意义。

- **安全**：密码 DPAPI 本地加密，永不上传；配置里只留用户名和地址
- **策略**：手动上传 / 下载为主，可选启动时自动拉取；配置带 `updated_at` + `device_id`，下载前比对时间戳，**不做后台自动合并**
- **冲突**：远端比本地新时弹一次确认（覆盖 / 保留本地），不做静默覆盖
- **兼容**：坚果云、Nextcloud、ownCloud、群晖、InfiniCLOUD（Basic Auth over HTTPS + `MKCOL` / `PUT` / `GET`）
- **证书**：默认只接受有效 HTTPS 证书。群晖等自签场景提供「允许自签」开关，默认关、开启时强提示
- **失败静默**：网络异常不阻塞切换功能，只在同步页显示状态

## 九、资源占用

| 状态 | 内存 | 说明 |
| --- | --- | --- |
| **托盘常驻**（开机自启 / 从未打开窗口） | **12 MB 工作集 / 2 MB 私有** | release 0.1.0 实测，进程树里 **0 个 WebView 进程** |
| 打开主界面 | **~432 MB 工作集 / ~224 MB 私有** | 共 7 个进程（WebView2 子进程）；工作集含共享页会重复计数，私有字节更接近真实 |
| 关闭主界面（隐藏窗口） | **仍是 ~228 MB 私有** | 窗口只隐藏，WebView 还活着；要真正释放只能退出应用 |
| 快捷语面板打开 | **~494 MB 工作集 / ~249 MB 私有** | 面板是第二个 WebView2 窗口；关闭面板后同样不释放 |
| 安装包 | **1.54 MB** | NSIS（`HexBench_0.1.0_x64-setup.exe`），未签名 |
| 对比 | Quicker 常驻 **210 MB** 工作集 | 本机实测 |

> **已知取舍**：关闭主界面后进程仍然常驻托盘，但 WebView 没被释放，所以「关窗口」不等于回到 12 MB。真正的做法是关闭时销毁主窗口、用一个无 WebView 的隐藏窗口维持事件循环；当前 Tauri 2.11 没有公开的无 WebView `WindowBuilder`，留到后续版本。

> **测量口径**（避免和竞品比较时口径不一）：应用空闲 5 分钟后，任务管理器读**工作集**与**私有字节**两个数，各取三次中位数。对外只报这两个值，不混用「物理内存」这种含糊说法。

其他稳定性设计：

| 项 | 做法 |
| --- | --- |
| 桌面引擎 | Windows 原生虚拟桌面，不自建，不与系统冲突 |
| 切换方式 | `SendInput` 发 `Win+Ctrl+←/→` —— 系统内置不可改快捷键，**不碰未公开 COM 接口，Windows 更新不会失效** |
| DPI | 清单声明 `PerMonitorV2`，全程物理像素；启动时用 150% 缩放自检坐标一致性 |
| 轮询 | 50 ms `GetCursorPos` + 缓存的显示器矩形，不用全局钩子；不调 `timeBeginPeriod`，避免拉高整机定时器精度 |

## 十、实现要点

| 部分 | 做法 |
| --- | --- |
| 显示器枚举 | `EnumDisplayMonitors` + `GetMonitorInfoW`，同时取 `rcMonitor`（物理像素）和 `rcWork` |
| 边缘判定 | 探头分段：断点取所有 `top`/`bottom`，逐段测中点，合并暴露段；结果缓存，布局变化才重算 |
| 触发带 | `M.bottom - M.height × ratio` 到 `M.bottom`，默认 10%；`position=top` 时贴 `M.top` |
| 任务栏排除 | `WindowFromPoint` 判类名 `Shell_TrayWnd` / `Shell_SecondaryTrayWnd` / `TrayNotifyWnd` / `MSTaskSwWClass`；不靠 `rcWork` 硬切，保住角落手感 |
| 触发检测 | 状态机 + 50 ms 轮询；`dwell` 计时用单调时钟，不用墙钟 |
| 切换桌面 | 一次 `SendInput` 提交 4 个按键，检查返回值；失败记 `GetLastError` + 一次性提示 |
| 虚拟桌面数量 | 读 `HKCU\...\Explorer\VirtualDesktops\VirtualDesktopIDs`（每个 GUID 16 字节）+ `CurrentVirtualDesktop` 定位当前是第几个；只有一个时界面提示并提供「新建虚拟桌面」（`SendInput` Win+Ctrl+D），新建后按真实步数（Windows 把新桌面追加在末尾）切回原桌面 |
| 全屏检测 | `SHQueryUserNotificationState`（`QUNS_RUNNING_D3D_FULL_SCREEN` / `QUNS_BUSY` / `QUNS_PRESENTATION_MODE`）+ 前台窗口矩形覆盖显示器（排除桌面、任务栏） |
| 锁屏检测 | `OpenInputDesktop(0, FALSE, DESKTOP_READOBJECTS)` 失败即视为锁屏/安全桌面，暂停 |
| 黑名单 | `GetForegroundWindow` → `GetWindowThreadProcessId` → `QueryFullProcessImageNameW`；提权进程取不到名字时退回窗口类名 |
| 布局变化 | 引擎线程建 `HWND_MESSAGE` 窗口跑消息循环，监听 `WM_DISPLAYCHANGE` / `WM_SETTINGCHANGE` / `WM_DPICHANGED`，**去抖 500 ms** 后重算 |
| 配置 | 单一 `config.json`，原子写 + `.bak`；`serde(default)` 保兼容 |
| 凭证 | DPAPI 加密存 `credentials.bin`，不进导出、不进同步 |
| 热键 | `RegisterHotKey`，失败时提示占用并要求改键；不静默降级 |
| 单实例 / 自启 | `tauri-plugin-single-instance` / `tauri-plugin-autostart`；自启带 `--autostart` 参数，不弹窗 |
| 日志 | `tauri-plugin-log`，滚动保留 7 天，不记录光标坐标 |
| 更新 | `tauri-plugin-updater` + 签名；关于页手动检查 + 可选自动检查 |
| 分发 | GitHub Actions 构建 → SignPath Foundation 免费 OSS 签名 → NSIS → winget / Scoop |
| 测试 | `hexbench-core` 单测（几何、配置、状态机）+ `--layout` CLI 回放布局并打印可触发区间 |

## 十三、风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| UIPI 拦截 `SendInput` | 提权前台时切换无效 | v0.1 实测；失败检测 + 提示；文档写明；不申请 `uiAccess` |
| 任务栏 / 自动隐藏冲突 | 误触发、抢开始按钮 | 类名排除；自动隐藏时提供"触发带换到顶部" |
| 杀软误报 | 安装被拦、进程被隔离 | 签名、不加壳、开源可审计、收集误报并申诉 |

## 发布一个更新

自动更新走 Tauri 官方链路：签名安装包 + `latest.json` 清单，客户端下载后由 NSIS 以 passive 模式静默安装，并用 `/R` 自动重启——用户只需要点一次「更新到 x.y.z」。

1. 版本号对齐：`Cargo.toml` 与 `src-tauri/tauri.conf.json` 都改成新版本（如 `0.1.3`）
2. 带私钥构建：

   ```powershell
   $env:TAURI_SIGNING_PRIVATE_KEY = ".tauri/hexbench.key"
   pnpm tauri build
   ```

   产物是 `target/release/bundle/nsis/HexBench_<v>_x64-setup.exe` 和同名 `.sig`
3. 把安装包与 `.sig` 传到 GitHub Release
4. 发布 `latest.json`（放 Release 资产，路径固定为 `releases/latest/download/latest.json`）：

   ```json
   {
     "version": "0.1.3",
     "notes": "本次更新内容",
     "pub_date": "2026-11-01T00:00:00Z",
     "platforms": {
       "windows-x86_64": {
         "signature": "<.sig 文件的内容>",
         "url": "https://github.com/hexbench/hexbench/releases/download/v0.1.3/HexBench_0.1.3_x64-setup.exe"
       }
     }
   }
   ```

客户端点「检查更新」→「更新到 0.1.3」即完成下载、安装与重启。

### 自动化

仓库里已经有两条流水线：

- `.github/workflows/ci.yml`：PR / main 上跑类型检查、`cargo test --workspace`、`cargo clippy -D warnings`
- `.github/workflows/release.yml`：打 `v*` tag 触发，签名构建 → `node scripts/latest-json.mjs` 生成清单 → 发布 Release（安装包、`.sig`、`latest.json`）

要在 GitHub 上启用自动发布，在仓库 Secrets 里配：

| Secret | 内容 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `.tauri/hexbench.key` 的**文件内容**（不是路径） |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 私钥口令，没设就留空 |

之后发版就三步：改版本号 → `git tag v0.1.3 && git push --tags` → 等流水线跑完。

手动发版时，`node scripts/latest-json.mjs` 也能在本地生成清单（`RELEASE_TAG` 指定 tag）。

注意：

- 私钥不要进仓库（`.tauri/` 已忽略）；**丢了私钥就再也无法给老版本推更新**
- 清单里的版本号必须和安装包实际版本一致，否则 updater 会以「签名版本不符」拒绝（这是防篡改校验）
- 端点必须是 https；本地联调时才临时开 `dangerousInsecureTransportProtocol`

### winget

`winget/` 下已经按 [winget-pkgs](https://github.com/microsoft/winget-pkgs) 的目录结构放好了三份清单（version / installer / locale），本地用 `winget validate --manifest winget\manifests\p\punwong\HexBench\0.1.3` 验证通过。

提交方式：把 `winget/manifests/p/punwong/HexBench/0.1.3` 整个目录复制到 fork 出来的 winget-pkgs 仓库的同名路径，开 PR 等审核。之后就能 `winget install punwong.HexBench`。

每次发版都要重新生成清单：改版本号、更新 `InstallerUrl`、用 `Get-FileHash` 填新的 `InstallerSha256`。
